# Сервис рекомендаций товаров для главной страницы

Сервис по идентификатору пользователя возвращает три товара для блока рекомендаций на главной странице интернет-магазина.

- **Бизнес-цель:** рост допродаж (оборота) за счёт блока рекомендаций.
- **Техническая метрика:** Precision@3 — доля рекомендованных товаров, купленных пользователем.
- **Результат:** Precision@3 = 0,0199 на отложенном тестовом периоде; рекомендация популярных товаров даёт 0,0099.

## 2. Исходные данные

Данные — лог интернет-магазина с 3 мая по 18 сентября 2015 года. Все файлы в формате CSV.

**`events.csv`** — лог событий, 2,76 млн строк.

| Колонка | Тип | Описание |
|---|---|---|
| `timestamp` | int64 | время события, Unix-время в миллисекундах |
| `visitorid` | int64 | идентификатор пользователя |
| `event` | str | `view` — просмотр, `addtocart` — добавление в корзину, `transaction` — покупка |
| `itemid` | int64 | идентификатор товара |
| `transactionid` | float64 | идентификатор транзакции, заполнен только у покупок |

**`category_tree.csv`** — дерево категорий, 1669 строк: `categoryid` и `parentid` (пусто у корневых категорий).

**`item_properties_part1.csv`, `item_properties_part2.csv`** — свойства товаров, 20,3 млн строк.

| Колонка | Тип | Описание |
|---|---|---|
| `timestamp` | int64 | момент записи значения (еженедельные снимки) |
| `itemid` | int64 | идентификатор товара |
| `property` | str | название свойства; все, кроме `categoryid` и `available`, захешированы |
| `value` | str | значение свойства; числа записаны с префиксом `n` |

## 3. Подготовка данных и факторы

### Трансформации исходных данных

1. Из лога событий удаляются полные дубликаты строк (460 штук), время переводится в `datetime`.
2. Файлы свойств читаются частями по 2 млн строк; остаются три свойства: `categoryid` (категория), `available` (наличие) и `790` (числовое свойство, заполненное у всех товаров).
3. Для каждой категории по дереву вычисляются родитель, корневая категория и глубина.
4. Обучающая выборка строится из временных срезов. Для среза с границей `cutoff`:
   - **объекты** — пары «пользователь–товар», встречавшиеся в событиях до `cutoff` (кандидаты);
   - **факторы** — считаются только по событиям и снимкам свойств до `cutoff`;
   - **целевая переменная** — 1, если пользователь купил товар в период `[cutoff, cutoff + 31 день)`, иначе 0;
   - оставляются все положительные примеры и случайные 20 % отрицательных.
5. Срезы берутся с шагом 7 дней начиная с 23 мая 2015 года и объединяются в одну таблицу.

### Формат обучающей таблицы

Одна строка — одна пара «пользователь–товар» на момент `cutoff`. Колонки `visitorid`, `itemid`, `target` и 41 фактор:

| Группа | Факторы | Описание |
|---|---|---|
| Пара «пользователь–товар» | `ui_views`, `ui_carts`, `ui_trans` | число просмотров, корзин и покупок товара пользователем |
| | `ui_days_since_last`, `ui_days_since_first` | дней с последнего и с первого взаимодействия |
| | `ui_active_days` | число дней, в которые были взаимодействия |
| | `ui_cart_no_buy` | товар добавлен в корзину, но не куплен |
| | `ui_recency_rank` | место товара в истории пользователя по давности (1 — последний) |
| | `ui_views_share` | доля просмотров товара среди всех просмотров пользователя |
| Пара «пользователь–категория» | `uc_views`, `uc_carts`, `uc_trans` | активность пользователя в категории товара |
| Пользователь | `user_views`, `user_carts`, `user_trans`, `user_items`, `user_active_days` | общая активность |
| | `user_cart_rate`, `user_buy_rate` | доля корзин и покупок от числа просмотров |
| | `user_days_since_last`, `user_days_since_first` | давность последнего и первого визита |
| Товар | `item_views`, `item_carts`, `item_trans`, `item_users` | популярность за всё время |
| | `item_7d_*`, `item_30d_*` | просмотры, корзины и покупки за последние 7 и 30 дней |
| | `item_cart_rate`, `item_buy_rate` | конверсии товара |
| | `item_days_since_last`, `item_days_since_first` | давность последнего и первого события |
| | `item_available`, `item_prop_790_log` | наличие и логарифм свойства 790 |
| Категория товара | `cat_depth`, `cat_views`, `cat_trans`, `cat_items` | глубина в дереве, популярность и размер категории |

Идентификаторы категорий (`categoryid`, `cat_parent`, `cat_root`) в модель не подаются. Пропуски в свойствах (примерно у пятой части товаров свойств нет) заполняются медианой.

## 4. Валидация

Используется разбиение по времени: модель обучается на прошлом и проверяется на будущем, как в реальной работе сервиса. Случайное разбиение привело бы к утечке будущих событий.

| Период | Даты | Назначение |
|---|---|---|
| Обучение | 3 мая — 17 июля 2015 | история и обучающие срезы для подбора |
| Валидация | 18 июля — 17 августа 2015 | выбор модели и гиперпараметров |
| Тест | 18 августа — 18 сентября 2015 | итоговая оценка, используется один раз |

Правила, исключающие утечку:

- факторы для периода считаются только по данным до его начала, включая свойства товаров;
- для подбора используются обучающие срезы, целевой период которых заканчивается до начала валидации (4 среза); для итоговой оценки — до начала теста (9 срезов).

**Расчёт метрики.** Для каждого пользователя, совершившего покупку в оцениваемом периоде, формируются три рекомендации; Precision@3 — доля купленных среди них, усреднённая по пользователям. Пользователи без истории получают три самых продаваемых товара за последние 30 дней.

## 5. Эксперименты

Все эксперименты приведены в ноутбуке `second_year_final_project_week3.ipynb`.

| Модель | Гиперпараметры | Precision@3, валидация | Precision@3, тест |
|---|---|---|---|
| **Логистическая регрессия на факторах** | `C=0.01`, пропуски — медиана, стандартизация; перебор `C` ∈ {0.01, 0.1, 1} | **0,0203** | **0,0199** |
| Градиентный бустинг на факторах (`HistGradientBoostingClassifier`) | `max_iter=200`, `learning_rate=0.05`, `max_leaf_nodes=7`, `min_samples_leaf=100`, `l2_regularization=1.0`; перебор 4 вариантов | 0,0198 | 0,0195 |
| Личная история (правило) | сначала товары из корзины, затем последние просмотренные | 0,0188 | 0,0192 |
| Коллаборативная фильтрация по товарам | косинусная близость, веса событий 1/3/5, `own_weight=1` | 0,0177 | 0,0166 |
| Матричная факторизация SVD | `TruncatedSVD`, 64 компоненты | 0,0115 | 0,0099 |
| Популярные товары | топ-3 по покупкам за 30 дней | 0,0111 | 0,0099 |

Выводы:

- Лучшая модель по валидации — логистическая регрессия на факторах. На тесте она вдвое точнее рекомендации популярных товаров, разница статистически значима (95 %-й доверительный интервал разности: от +0,0077 до +0,0125).
- Преимущество перед простым правилом «личная история» статистически не значимо (148 удачных рекомендаций против 143).
- Только 14 % покупателей тестового периода имеют историю. Для них Precision@3 модели равен 0,088, для остальных доступны только популярные товары (0,009), поэтому общее значение метрики невелико.
- Сильнее всего на решение модели влияют давность взаимодействия пользователя с товаром, наличие товара, признак «в корзине, но не куплен» и давность последнего события с товаром.

## 6. Устройство сервиса

Рекомендации рассчитываются заранее, сервис только выдаёт готовый результат.

1. **Обучение (`train.py`).** Скрипт обучает модель, считает факторы на конец доступных данных, оценивает вероятность покупки каждого товара из истории каждого пользователя и сохраняет по три лучших товара в `artifacts/recommendations.npz`. Свободные места заполняются популярными товарами.
2. **Сервис (`app.py`).** При запуске загружает файл с рекомендациями в память (1,4 млн пользователей, около 30 МБ). Запрос обрабатывается двоичным поиском по массиву идентификаторов, без обращения к модели, поэтому ответ занимает менее миллисекунды.
3. **Пользователи без истории** получают три самых продаваемых товара за последние 30 дней; в ответе это отмечено полем `personalized: false`.

В Docker-образ входят только `app.py`, файл с рекомендациями и `model_info.json`. Зависимости сервиса: Flask, NumPy, gunicorn.

## 7. Запуск в Docker

Все команды выполняются из папки `recsys`.

**Собрать образ**

```bash
docker build -t recsys-service:1.0 .
```

**Запустить сервис**

```bash
docker run -d --name recsys -p 8000:8000 recsys-service:1.0
```

Сервис будет доступен по адресу `http://localhost:8000`. Проверка:

```bash
curl http://localhost:8000/health
```

**Выгрузить образ в файл и загрузить на другой машине**

```bash
docker save -o recsys-service.tar recsys-service:1.0
docker load -i recsys-service.tar
docker run -d --name recsys -p 8000:8000 recsys-service:1.0
```

**Остановить и удалить контейнер**

```bash
docker stop recsys
docker rm recsys
```

**Логи сервиса**

```bash
docker logs recsys
```

В контейнере сервис запускается командой `gunicorn --bind 0.0.0.0:8000 --workers 1 --threads 8 app:app` от имени непривилегированного пользователя. Используется один процесс с несколькими потоками, чтобы счётчики `/metrics` были общими для всех запросов.

**Запуск без Docker** (для отладки):

```bash
pip install -r requirements.txt
python app.py
```

## 8. API сервиса

Все ответы, кроме `/metrics`, возвращаются в формате JSON в кодировке UTF-8.

| Метод и адрес | Назначение |
|---|---|
| `GET /recommend/<user_id>` | рекомендации для одного пользователя |
| `POST /recommend` | рекомендации для списка пользователей |
| `GET /health` | проверка состояния сервиса |
| `GET /info` | описание модели, факторов и метрик качества |
| `GET /metrics` | метрики сервиса в формате Prometheus |
| `GET /` | краткая справка по адресам |

### `GET /recommend/<user_id>`

Параметры:

- `user_id` — идентификатор пользователя (`visitorid`), целое неотрицательное число;
- `k` — необязательный параметр строки запроса, число рекомендаций от 1 до 3 (по умолчанию 3).

```bash
curl http://localhost:8000/recommend/1000
```

```json
{"items": [248975, 461686, 213834], "model_version": "20261116-121937", "personalized": true, "user_id": 1000}
```

Поля ответа:

- `items` — идентификаторы рекомендованных товаров в порядке убывания приоритета;
- `personalized` — `true`, если рекомендации построены по истории пользователя; `false`, если пользователь неизвестен и возвращены популярные товары;
- `model_version` — версия модели (дата и время обучения, UTC).

Неизвестный пользователь — не ошибка:

```bash
curl http://localhost:8000/recommend/999999999
```

```json
{"items": [461686, 213834, 334401], "model_version": "20261116-121937", "personalized": false, "user_id": 999999999}
```

### `POST /recommend`

Тело запроса — JSON-объект: `user_ids` — список идентификаторов (от 1 до 1000 штук), `k` — необязательное число рекомендаций.

```bash
curl -X POST http://localhost:8000/recommend -H "Content-Type: application/json" -d "{\"user_ids\": [1000, 999999999], \"k\": 3}"
```

```json
{
  "model_version": "20261116-121937",
  "recommendations": [
    {"items": [248975, 461686, 213834], "personalized": true, "user_id": 1000},
    {"items": [461686, 213834, 334401], "personalized": false, "user_id": 999999999}
  ]
}
```

### `GET /health`

```json
{"model_version": "20261116-121937", "status": "ok", "users": 1407580}
```

### `GET /metrics`

Текст в формате Prometheus:

| Метрика | Описание |
|---|---|
| `recsys_requests_total{endpoint, method, status}` | число запросов по адресам, методам и кодам ответа |
| `recsys_request_duration_seconds` | гистограмма времени обработки запросов по адресам |
| `recsys_recommendations_total{type}` | число выданных рекомендаций: `personalized` и `popular` |
| `recsys_uptime_seconds` | время работы сервиса |
| `recsys_model_users` | число пользователей с персональными рекомендациями |
| `recsys_model_precision_at_3` | Precision@3 модели на тестовом периоде |
| `recsys_model_info{version}` | версия модели |

### Ошибки

При ошибке возвращается JSON вида `{"error": "описание"}`.

| Код | Когда возвращается |
|---|---|
| 400 | `user_id` не является целым неотрицательным числом; `k` вне диапазона 1–3; тело запроса не JSON-объект; `user_ids` пуст, не список или длиннее 1000 |
| 404 | адрес не существует |
| 405 | метод не поддерживается для адреса |
| 413 | тело запроса больше 1 МБ |
| 500 | внутренняя ошибка сервиса |

```bash
curl http://localhost:8000/recommend/abc
```

```json
{"error": "user_id должен быть целым неотрицательным числом, получено: 'abc'"}
```

## 9. Переобучение модели

```bash
pip install -r requirements-train.txt
python train.py --data-dir .. --out-dir artifacts
```

Скрипт выполняет два этапа (около 3–5 минут):

1. обучает модель на данных до 18 августа и считает Precision@3 на тестовом периоде — значение записывается в `model_info.json`;
2. переобучает модель с теми же гиперпараметрами на всех данных (13 срезов) и рассчитывает рекомендации для всех пользователей.

После переобучения образ нужно собрать заново: `docker build -t recsys-service:1.0 .`

## 10. Ограничения

- Рекомендации рассчитываются пакетно и не учитывают действия пользователя после момента расчёта. Чтобы учитывать текущую сессию, нужен поток событий в реальном времени.
- Новые пользователи получают одинаковые популярные товары.
- Офлайн-метрика посчитана по покупкам, совершённым без блока рекомендаций. Реальное влияние на допродажи нужно проверять A/B-тестом.
